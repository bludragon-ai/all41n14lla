## Finding 1 (BLOCKER) — multi-word recall returned "No matches."

**Fix: `src/all41n14lla/engine/search.py:16-38` (`_sanitize`).**

- Old: wrapped the whole query in one pair of quotes → an FTS5 *phrase* query
  requiring the terms to be ADJACENT. `recall "sqlite tokenizer"` against
  "sqlite fts5 uses the porter tokenizer by default" → zero matches.
- New: each whitespace-separated term is quoted as its own phrase and joined
  with FTS5's **implicit AND** — every term must appear, in any position.
  Operators (`AND`/`OR`/`NOT`/`NEAR`, `-`, `:`, `*`, parens) stay neutralized
  as literal words; terms with no alphanumerics are dropped (an empty FTS5
  phrase is a syntax error).
- Semantics decision (was a J-tap): chose **AND-joined terms** over OR.
  Rationale: AND is what users expect from a search box, it is FTS5's own
  default for unquoted multi-term queries, and OR would flood recall with
  single-term noise. Tested: AND is enforced by
  `tests/test_search.py::test_and_semantics_requires_all_terms`. Flipping to
  OR later is a one-line change in `_sanitize` (`" OR ".join`).
  > **Superseded 2026-07 (recorded 2026-08-04):** recall now ships **OR + BM25**
  > (`" OR ".join` in `search.py`) — the flip this paragraph predicted happened,
  > because AND silently returned `[]` for natural multi-word recalls. The test
  > named above was replaced by
  > `test_or_semantics_partial_match_does_not_veto`. This section stands as the
  > record of the original decision only; do not restore AND from it.
- Fixes both the CLI path and the MCP server's `recall` tool (same code path).
- Side effect: stale comment removed at `tests/test_retrieval.py:213`
  ("lexical search is phrase-matched — use a contiguous phrase" — no longer
  true).
- Proof: `all41n14lla init` → `remember concept "sqlite fts5 uses the porter
  tokenizer by default"` → `recall "sqlite tokenizer"` returns the concept
  (was: "No matches.").

**Regression tests:** `tests/test_search.py` (12 tests — sanitize unit

## Finding 4 (HIGH) — install exceeded the 3-step rule → one-command goal

**New: `all41n14lla wire` — `src/all41n14lla/wire.py` (new module, 268
lines) + `src/all41n14lla/cli.py:396-475` (new `wire` command).**

- Detects installed MCP clients (Claude Code by `~/.claude.json`; Claude
  Desktop, Cursor, Gemini CLI, Codex CLI by config dir) and adds the server
  block to each.
- **Idempotent** — second run reports "already wired", changes zero bytes
  (test-proven by file snapshot comparison).
- **`--dry-run`** — prints exactly what would be written, writes nothing.
- **Never destructive** — backs up any config it modifies to
  `<name>.all41n14lla.bak` first; a differing existing entry is a CONFLICT
  (reported, not overwritten; `--force` replaces it, JSON clients only);
  unparseable configs are skipped with an error and left byte-identical;
  TOML output is re-parsed with `tomllib` before writing.
- Uses the absolute binary path by default (kills the #1 Claude Desktop
  restricted-PATH failure); embeds `ALL41N14LLA_VAULT` when set or passed.
- Zero new dependencies (stdlib `json` + `tomllib` + `shutil`).
- `README.md:37-55` — old: "From PyPI" (1 cmd) + "From source" (5 commands)
  → new: one command (`pipx install all41n14lla && all41n14lla init &&
  all41n14lla wire`), the same thing as 3 numbered steps, an honest
  "`wire` is in main, unreleased" note for 0.1.0 wheel users, and a pointer
  to CONTRIBUTING for the from-source path (content moved, not lost).
- `CONTRIBUTING.md:10-15` — from-source setup compressed to clone / cd /
  one-liner (venv + activate + install).
- Decision: no `install.sh`. The pipx one-liner is the same length,
  auditable, and avoids the curl|bash anti-pattern this project's audience
  would (rightly) side-eye.

**Tests:** `tests/test_wire.py` (15 tests — detection, dry-run writes
